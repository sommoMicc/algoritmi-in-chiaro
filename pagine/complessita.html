Fondamenti

Complessità e notazione asintotica

All'esame era una domanda teorica. Sul lavoro è la differenza tra un endpoint che regge e uno che crolla quando la tabella passa da mille a un milione di righe. Ripassiamo il linguaggio per dirlo in fretta: O, Omega e Theta.

O, Ω, Θ tempo e spazio caso migliore, medio, peggiore

L'idea

Immagina due modi per trovare un nome in una rubrica con n voci. Il primo scorre la lista dall'inizio: nel caso peggiore legge tutte le n voci. Il secondo, se la rubrica è in ordine alfabetico, può saltare a metà e scartare un pezzo intero a ogni confronto. Il primo cresce in modo lineare, il secondo in modo logaritmico. Su dieci elementi quasi non li distingui; su dieci milioni la differenza è enorme.

La complessità temporale misura (in modo astratto) quanti passi fondamentali fa un algoritmo in funzione della dimensione dell'input, di solito chiamata n. La complessità spaziale misura la memoria aggiuntiva che gli serve. Non contiamo i millisecondi su un computer particolare: quei numeri dipendono dal processore, dal linguaggio, dal carico del sistema. Contiamo invece come cresce il lavoro quando n diventa grande.

Dove lo rivedi sul lavoro

Un .find() o un .includes() dentro un ciclo che diventa O(n²) senza che nessuno se ne accorga; la query N+1 dell'ORM; la scelta tra un array e un Set/Map per i lookup (O(n) contro O(1) in media); una paginazione che rilegge tutto a ogni pagina. Riconoscere la classe di crescita a colpo d'occhio è la competenza più utile di tutta questa materia.

O, Omega e Theta

Tre simboli tornano in ogni libro e in ogni esame. Vale la pena tenerli distinti.

SimboloNomeCosa significa, in pratica
O(f(n)) O-grande (Big-O) È un limite superiore. Il lavoro, da un certo n in poi, non cresce più in fretta di una costante per f(n). Dire «è O(n²)» vuol dire «non è peggio di quadratico» — potrebbe anche essere meglio.
Ω(f(n)) Omega-grande È un limite inferiore. Il lavoro è almeno dell'ordine di f(n). Utile quando vuoi dire che un problema, o un algoritmo, non può fare meno di una certa quantità di fatica.
Θ(f(n)) Theta-grande È un bound stretto: vale sia O sia Ω. Se un ciclo fa sempre circa n / 2 confronti, è Θ(n). Quando possiamo, è la notazione più informativa.

Nella pratica quotidiana

Molti articoli e discussioni usano «O-grande» anche quando intendono Theta: «binary search è O(log n)» è vero, e in realtà è anche Θ(log n) nel caso peggiore. Qui cerchiamo di essere precisi, ma non ti fare prendere dal panico se in rete i due simboli si mescolano.

Come si «pulisce» una formula

Se un algoritmo fa 3n² + 10n + 40 confronti, per n grande il termine 3n² domina. La notazione asintotica butta via le costanti e i termini di grado inferiore, e scrive Θ(n²). Non è pigra: sta isolando il comportamento che conta quando l'input cresce.

Regole utili, da prendere con un po' di giudizio:

  • si ignorano le costanti moltiplicative: 100n e 2n sono entrambi Θ(n);
  • si tiene il termine che cresce più in fretta: n² + n log n + 7 è Θ(n²);
  • i logaritmi in basi diverse differiscono solo per una costante, quindi O(log2 n) e O(log10 n) sono la stessa classe;
  • quando sommi due pezzi indipendenti, vince il più costoso: leggere un array Θ(n) e poi una ricerca binaria Θ(log n) resta Θ(n).

Caso migliore, medio, peggiore

Lo stesso algoritmo può avere costi diversi a seconda dei dati. La ricerca lineare, se l'elemento è il primo, fa un solo confronto (caso migliore, Θ(1)); se manca del tutto, ne fa n (caso peggiore, Θ(n)). La ricerca binaria, su un array già ordinato, è Θ(log n) nel caso peggiore e può terminare prima se trova il valore a metà strada.

Quando non è detto altro, si parla di solito del caso peggiore: è una garanzia. Il caso medio richiede un'ipotesi su come sono fatti gli input (per esempio «tutte le permutazioni sono equiprobabili») ed è più delicato da calcolare. Quick Sort è l'esempio classico: Θ(n log n) in media, Θ(n²) nel peggiore.

Le costanti, a volte, contano

O(n log n) è asintoticamente migliore di O(n²), ma su array minuscoli un Insertion Sort ben scritto può battere un Merge Sort, perché ha meno lavoro «fisso» e usa meglio la cache. La notazione asintotica è una bussola, non un cronometro. Quando n è piccolo o i fattori nascosti sono grandi, si misura.

Un esempio guidato

Quante operazioni fa questo frammento?

function contaCoppie(a) {
  let tot = 0;                 // Θ(1)
  for (let i = 0; i < a.length; i++) {     // n iterazioni
    for (let j = i + 1; j < a.length; j++) { // fino a n-1, n-2, …
      if (a[i] + a[j] === 0) tot++;
    }
  }
  return tot;
}
def conta_coppie(a):
    tot = 0                  # Θ(1)
    for i in range(len(a)):  # n iterazioni
        for j in range(i + 1, len(a)):
            if a[i] + a[j] == 0:
                tot += 1
    return tot

Il ciclo interno, al variare di i, fa n-1 + n-2 + … + 1 confronti, cioè n(n-1)/2. È Θ(n²) nel tempo e Θ(1) nello spazio extra (oltre all'array già in memoria). Non è «circa n² a volte»: lo è sempre, indipendentemente dai valori.

Esercizi

1. Quale bound è più stretto?

Un algoritmo fa sempre 5n + 3 passi. Quali affermazioni sono vere? (a) è O(n) (b) è O(n²) (c) è Θ(n) (d) è Ω(n²).

Mostra la soluzione

Vere: (a), (b) e (c). O(n²) è un limite superiore corretto, anche se largo. (d) è falsa: il lavoro non cresce almeno come n².

2. Due cicli in fila

Un algoritmo scorre un array una volta e poi esegue una ricerca binaria sullo stesso array, già ordinato. Qual è la complessità totale nel caso peggiore?

Mostra la soluzione

Θ(n) + Θ(log n) = Θ(n). Il termine lineare nasconde quello logaritmico.

3. Una trappola classica

Perché è impreciso dire «O(n) è sempre più veloce di O(n²)»?

Mostra la soluzione

Perché O descrive una crescita asintotica, non un tempo assoluto. Un algoritmo 10000·n può essere più lento di 0,001·n² su n piccoli. Inoltre O(n) è un limite superiore: un algoritmo dichiarato O(n) potrebbe, in realtà, essere anche O(1). Si confrontano con più onestà i bound stretti (Theta) e, quando serve, si misurano i tempi reali.

Ordinamento

Merge Sort

Invece di scambiare vicini, spezzi il problema a metà, ordini le due parti e le unisci. Il risultato è un ordinamento prevedibile: Θ(n log n) sempre, al prezzo di un po' di memoria extra.

Tempo Θ(n log n) Spazio O(n) Stabile Divide et impera

L'idea

Merge Sort è il manifesto della tecnica divide et impera. Se l'array ha zero o un elemento, è già ordinato: è il caso base. Altrimenti:

  1. dividi l'array in due metà (quasi) uguali;
  2. risolvi ricorsivamente ciascuna metà;
  3. combina le due metà già ordinate in una sola sequenza ordinata, con la procedura di merge.

Il cuore è proprio l'unione. Hai due file di persone già messe in altezza: per costruire una fila unica basta confrontare i due in testa e far avanzare il più basso, e ripetere. Ogni elemento viene guardato una volta sola, quindi fondere due sequenze di lunghezza complessiva n costa Θ(n). L'albero della ricorsione è alto Θ(log n) livelli, e a ogni livello, sommati insieme, i merge costano Θ(n). Totale: Θ(n log n).

A differenza di Bubble Sort, il tempo non dipende dai dati: un array già ordinato, uno mescolato e uno capovolto fanno lo stesso ordine di lavoro. In cambio serve un array di appoggio per il merge, quindi O(n) memoria extra.

Dove lo rivedi sul lavoro

TimSort, l'ordinamento di list.sort in Python e di Array.prototype.sort in V8, è un Merge Sort adattivo: per questo è stabile, e la stabilità è garantita dallo standard JavaScript dal 2019. Il merge di due sequenze ordinate torna nei merge join dei database, nell'ordinamento esterno di file troppo grandi per la RAM, e nell'unione di stream o log già ordinati per timestamp.

Pseudocodice e codice

MERGE-SORT(A, low, high)
  se low ≥ high
    termina
  mid ← ⌊(low + high) / 2⌋
  MERGE-SORT(A, low, mid)
  MERGE-SORT(A, mid + 1, high)
  MERGE(A, low, mid, high)

MERGE(A, low, mid, high)
  crea un array temporaneo T
  i ← low, j ← mid + 1
  mentre i ≤ mid e j ≤ high
    se A[i] ≤ A[j]
      appendi A[i] a T, i ← i + 1
    altrimenti
      appendi A[j] a T, j ← j + 1
  appendi a T gli eventuali resti di A[i..mid] e A[j..high]
  copia T in A[low..high]
function mergeSort(a) {
  if (a.length <= 1) return a.slice();
  const mid = Math.floor(a.length / 2);
  return merge(mergeSort(a.slice(0, mid)), mergeSort(a.slice(mid)));
}

function merge(left, right) {
  const out = [];
  let i = 0, j = 0;
  while (i < left.length && j < right.length) {
    if (left[i] <= right[j]) out.push(left[i++]);
    else out.push(right[j++]);
  }
  return out.concat(left.slice(i), right.slice(j));
}
def merge_sort(a):

def merge(left, right):
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

La versione qui sopra, per chiarezza, costruisce nuovi array a ogni chiamata. In una implementazione in-place «di lavoro» si riusa un solo buffer ausiliario di lunghezza n e si ragiona su indici, come nello pseudocodice. La complessità asintotica non cambia; cambia l'uso concreto della memoria e della cache.

Complessità

TempoSpazio extra
Caso migliore, medio e peggioreΘ(n log n)O(n)

La ricorrenza classica è T(n) = 2 T(n/2) + Θ(n), con T(1) = Θ(1). Il teorema master (caso 2) la risolve come Θ(n log n). Si può vedere anche «a livelli»: log2 n livelli di ricorsione, costo Θ(n) per livello.

Merge Sort è stabile se, a parità di chiave, nel merge prendi prima l'elemento della metà sinistra (≤ e non <). Non è in-place nella forma usuale: esiste una variante in-place, ma è più delicata e meno usata in pratica. Per chi vuole un O(n log n) in-place e non ha bisogno di stabilità, Heap Sort è l'alternativa tipica; Quick Sort, in media, è spesso più veloce ma ha un caso peggiore quadratico se il pivot è scelto male.

Un confronto rapido con Bubble Sort

Su n = 1.000, Bubble Sort può arrivare a circa mezzo milione di confronti; Merge Sort ne fa dell'ordine di 10.000. Su n = 1.000.000 il primo diventa impraticabile, il secondo resta nella decina di milioni di operazioni: del tutto ragionevole. Il prezzo è l'array temporaneo. Quando la memoria è stretta o n è minuscolo, la scelta può cambiare; quando n cresce, Merge Sort (o un suo cugino n log n) vince senza discussione.

Esercizi

1. Un merge a mano

Unisci le due sequenze già ordinate [1, 4, 7] e [2, 3, 8]. In che ordine vengono scelti gli elementi?

Mostra la soluzione

1 (da sinistra), 2, 3 (da destra), 4, 7 (da sinistra), 8. Risultato: [1, 2, 3, 4, 7, 8].

2. Altezza dell'albero

Quanti livelli di divisione fa Merge Sort su un array di 8 elementi, caso base escluso?

Mostra la soluzione

Tre livelli (8→4, 4→2, 2→1), cioè log2 8 = 3. Poi si risale unendo. Su n che non è una potenza di 2 le metà non sono sempre uguali, ma l'altezza resta Θ(log n).

3. Perché Θ, non solo O

Perché di Merge Sort si può dire Θ(n log n) anche nel caso migliore, a differenza di Bubble Sort con bandierina?

Mostra la soluzione

Perché l'algoritmo divide comunque fino al caso base e esegue tutti i merge. Non c'è una scorciatoia che riconosca un array già ordinato e termini in tempo lineare (a meno di varianti diverse, come un controllo extra prima di fondere: in quel caso il migliore può scendere, ma non è il Merge Sort classico). Il lavoro è quindi dello stesso ordine su ogni input.
